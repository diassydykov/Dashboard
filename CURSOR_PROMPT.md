# Промт для Cursor: конструктор школьного расписания

Скопируй текст ниже целиком в Cursor в репозитории `diassydykov/Dashboard`. Перед началом работы проверь текущую структуру проекта и не удаляй пользовательские изменения.

---

Ты senior full-stack разработчик и продуктовый инженер. Создай production-ready MVP веб-платформы для администрации двух общеобразовательных школ Казахстана: конструктор школьного расписания на 2026–2027 учебный год. Интерфейс и все шаблоны должны быть на русском языке. Деплой будет на Vercel, поэтому решение должно быть совместимо с Vercel и не зависеть от локального файлового хранилища или SQLite в production.

## Цель

Завуч создаёт учебный год, настраивает две смены и время уроков/перемен, импортирует классы и педагогов из Excel, задаёт учебную нагрузку и получает черновик расписания. Система не должна допускать конфликтов: один учитель не может вести два урока одновременно, один класс не может иметь два урока одновременно, а кабинет (если указан) не может использоваться дважды в один слот. Завуч может вручную править расписание, а система должна сразу показывать и блокировать конфликты.

Это инструмент для двух школ, не публичный маркетплейс. Сначала нужен качественный работающий MVP с чистой архитектурой, а не попытка сразу охватить все особенности каждой школы.

## Технологии и ограничения

- Next.js (App Router), TypeScript, React, Tailwind CSS.
- PostgreSQL через Supabase; миграции и типобезопасный ORM (Prisma либо Drizzle — выбери один и последовательно используй). Не используй SQLite для production.
- Авторизация по email/password или magic link через Supabase Auth. Роли: `super_admin`, `school_admin` (завуч), `viewer`.
- Строгая изоляция данных по `schoolId`: пользователь не может читать или менять записи другой школы. Реализуй проверку на сервере и RLS в Supabase, если используешь его клиент напрямую.
- Валидация на сервере и клиенте: Zod. Формы: React Hook Form.
- Excel: SheetJS (`xlsx`). Генерация шаблонов `.xlsx`, импорт, строгая проверка колонок, предпросмотр строк, понятный отчёт об ошибках и подтверждение импорта. Никогда не записывай частично невалидный импорт.
- Не используй платные внешние API и не закладывай зависимость от LLM для построения расписания.
- Добавь `.env.example` без секретов и подробный README с локальным запуском, переменными окружения, миграциями Supabase и инструкцией Vercel.

## Доменная модель

Сделай схему, позволяющую в будущем расширять систему, но не усложняй без необходимости:

- `School`, `UserProfile`, `AcademicYear`.
- `Grade` (параллель), `ClassGroup` (например, 5 «А»), язык обучения, смена, допустимые дни/слоты.
- `Teacher`, его ФИО, сокращённое имя, email/телефон опционально, активность.
- `Subject` и связь «учитель — предмет».
- `Room` опционально.
- `CurriculumRequirement`: школа + учебный год + класс/параллель + предмет + часов в неделю + предпочтительный учитель. Храни именно часов в неделю; при необходимости отображай расчёт за год, используя настраиваемое число учебных недель.
- `BellSchedule`: смена, день недели, номер урока, время начала/окончания; перемена задаётся как разрыв между уроками. Должны поддерживаться разные длительности урока (30, 35, 40, 45 минут) по классам и сменам.
- `Lesson`: класс, предмет, учитель, кабинет, день, смена, номер урока, длительность/временной слот.
- `ImportBatch`/журнал импорта и `ScheduleVersion` (минимально: черновик и опубликованная версия).

Уникальные ограничения в БД должны защищать от конфликтов по школе + учебному году + дню + времени: для класса, учителя и кабинета. Если хранение через номер урока недостаточно при разных длительностях, проверяй реальное пересечение интервалов времени в серверной бизнес-логике.

## Пользовательские сценарии и страницы

1. Вход и выбор школы (только для `super_admin`, иначе сразу своя школа).
2. Дашборд: выбранные школа и учебный год, состояние заполнения данных, число конфликтов, быстрые действия.
3. «Настройки звонков»:
   - две смены;
   - количество уроков в день;
   - ручное задание начала/окончания каждого урока и перемен;
   - профили длительности уроков для групп классов;
   - визуальная временная шкала и серверная проверка, что интервалы не пересекаются.
4. «Импорт данных»:
   - кнопки скачать шаблоны: `Классы.xlsx`, `Учителя.xlsx`, `Учебная нагрузка.xlsx`, дополнительно `Кабинеты.xlsx`;
   - на странице укажи обязательные колонки и образец одной строки;
   - шаблон классов: `Параллель`, `Буква`, `Язык обучения`, `Смена`;
   - шаблон учителей: `ФИО`, `Краткое имя`, `Email`, `Предметы`;
   - шаблон нагрузки: `Класс`, `Предмет`, `Часов в неделю`, `Учитель`, `Кабинет`, `Разрешённые дни`;
   - валидация дублей, несуществующих классов/учителей/предметов, неверных чисел, пустых обязательных значений; покажи номер строки и причину;
   - импорт должен быть идемпотентным: выбери и явно реализуй стратегию «заменить данные этого типа после подтверждения» либо upsert по естественному ключу. Объясни её в UI.
5. «Учебный план»: CRUD справочников и таблица нагрузки. ВАЖНО: не зашивай нормативные часы из методички в код. Методичка является справочным документом; нормативы должны быть версионируемыми и редактируемыми завучем/импортом, потому что зависят от языка обучения, типа плана, деления класса и локальных решений школы.
6. «Расписание»:
   - недельная сетка Пн–Пт/Сб (суббота включается настройкой), фильтры класс / учитель / кабинет / смена;
   - создание, редактирование, удаление урока через удобную форму;
   - выделение конфликтов, предупреждение о превышении/недоборе недельной нагрузки по предмету;
   - создание черновика «Сгенерировать расписание» и отдельное действие «Опубликовать» после валидации.
7. Экспорт расписания класса и учителя в Excel; печатная версия страницы.

## Алгоритм генерации

Реализуй детерминированный генератор без «магии»:

1. Из каждой записи нагрузки сформируй нужное число еженедельных уроков.
2. Сначала размещай наиболее ограниченные уроки: преподаватель с наименьшим числом свободных слотов, затем предметы с большим количеством часов.
3. Используй backtracking с ограничением по времени/числу итераций, эвристику MRV и seed для воспроизводимости. Не генерируй расписание бесконечно.
4. Жёсткие ограничения: отсутствие пересечений по классу, учителю и кабинету; допустимая смена и доступные временные слоты; назначенный преподаватель; нужное число уроков в неделю.
5. Мягкие ограничения с понятным штрафом: не больше двух одинаковых уроков в день по умолчанию, равномерное распределение предмета по неделе, минимизация окон у учителя, нежелательные дни/слоты.
6. Результат: либо валидный черновик, либо честный отчёт о неразмещённых уроках с причиной и предложением, какие ограничения ослабить. Никогда не публикуй конфликтное расписание.
7. Напиши unit-тесты на минимум: конфликт учителя, конфликт класса, конфликт кабинета, корректное количество часов, невозможный набор ограничений.

## UX, доступность и безопасность

- Адаптивный, спокойный административный интерфейс на русском; хорошая работа на ноутбуке и планшете.
- Понятные пустые состояния и пошаговый onboarding: 1) школа/год, 2) звонки, 3) импорт, 4) нагрузка, 5) генерация.
- Подтверждение опасных операций и возможность скачать отчёт об ошибках импорта.
- Не выводи в клиент секреты, не доверяй `schoolId` из URL без серверной проверки, не используй `any`, не отключай TypeScript/ESLint.
- Проверь часовой пояс `Asia/Almaty` для отображения дат; времена уроков храни как локальные `HH:mm`, без ненужного перевода в UTC.

## Порядок работы

1. Сначала осмотри существующий репозиторий и кратко опиши план реализации.
2. Создай базовый каркас, БД-схему, миграции и сиды демонстрационных данных для одной школы.
3. Реализуй вертикальный срез: авторизация → настройка звонков → импорт шаблона классов/учителей/нагрузки → ручная сетка → валидация конфликтов.
4. Затем добавь генератор, экспорт и тесты.
5. После каждого крупного этапа запускай `lint`, проверку типов и тесты; исправляй ошибки до перехода дальше.
6. В конце покажи список изменённых файлов, команды запуска и известные ограничения MVP.

## Критерии готовности MVP

- На Vercel приложение собирается без ошибок при заполненных переменных окружения.
- Завуч может настроить две смены с разным расписанием звонков и длительностью уроков.
- Можно скачать Excel-шаблоны, заполнить их, увидеть ошибки до импорта и успешно импортировать корректные данные.
- Ручное создание конфликтного урока отклоняется сервером и наглядно объясняется в интерфейсе.
- Генератор создаёт черновик без жёстких конфликтов или выдаёт диагностический отчёт.
- Нагрузку по предметам видно в виде «требуется / запланировано / осталось».
- Есть тесты критичных ограничений, README и `.env.example`.

Не добавляй фиктивную интеграцию оплаты, публичный каталог школ или чрезмерно сложный ИИ. Если нормативных данных недостаточно, используй редактируемые демо-данные и пометь их как демонстрационные, а не как официальные нормы.
